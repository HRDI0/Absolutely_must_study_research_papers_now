# 문서 길이와 학습 기록 규칙

[학습 지도](README.md) · [홈](../README.md)

## 길이 제한

현재 과정의 Markdown은 **120줄 또는 6,000자 중 하나를 넘기기 전에 분리**합니다. 줄 수는 빈 줄을 포함하고, 글자 수는 공백·링크·표·코드 블록을 포함합니다. UTF-8 byte 수와 혼동하지 않습니다. 긴 URL도 글자 수에 포함합니다.

주제의 끝에서 나누고 문장·표·수식·코드 블록의 중간을 자르지 않습니다. 표 하나가 너무 크면 범주별로 나누고 각각 표 머리글을 둡니다. 파일 이름은 내용을 드러내는 이름을 우선합니다.

## 파일별 역할

| 파일 | 역할 |
|---|---|
| 주차 README.md | 목표·읽을 자료·순서·완료 체크·짧은 기록 |
| 주차 WORKBOOK.md | 손계산·입력/기대 결과·단계별 힌트·실패 진단 |
| 주차 NOTES-01.md | 길어진 풀이·질문·실험 기록의 첫 파일 |
| NOTES-02.md 이후 | 이전 기록을 지우지 않고 이어지는 기록 |
| target의 주제별 문서 | 공통 설정·환경·비교 절차; 주차에서 필요할 때 직접 연결 |

내용이 짧으면 새 파일을 미리 만들지 않습니다. README에서 보조 문서로 한 번 이동한 뒤 README로 돌아오면 다음 주로 갈 수 있게 합니다. 완료 체크를 두 파일에서 중복 관리하지 않습니다.

## 기록이 길어졌을 때

1. 현재 파일이 한계에 가까워지면 지금 실험/주제까지 마칩니다.
2. 같은 폴더에 다음 번호의 NOTES 파일을 만듭니다.
3. 이전 파일 끝에 다음 파일 링크, 새 파일 위에 이전 파일과 주차 README 링크를 적습니다.
4. 주차 README의 “내 기록”에는 최신 기록 링크 하나만 갱신합니다.
5. 이전 메모와 실패 결과는 그대로 둡니다. 결과가 바뀌면 정정 날짜와 후속 기록을 연결합니다.

자동 분할 프로그램을 추가한 것은 아닙니다. 사람과 이후 문서 작업자가 따르는 저장 규칙이며, 이번 보강에서는 실제 길이를 측정해 분리했습니다.

## NOTES 파일의 최소 구성

- 제목: N주차 기록 01
- 이동: 주차 README / 이전 기록 / 다음 기록(생겼을 때만)
- 날짜·이번 질문
- 입력·예상 결과·실제 결과
- 내가 시도한 것·실패 원인
- GPT/영상/원문에서 받은 힌트와 확인 근거
- 다음 작업

새 파일을 만들 때 비어 있는 링크나 존재하지 않는 “다음 기록” 링크를 미리 넣지 않습니다.

## 적용 범위

현재 사용하는 README·resources·target·curriculum 문서에 적용합니다. archive의 과거 과정과 개인 기록은 보존 자료이므로 이번 길이 규칙을 소급 적용하지 않습니다. 보관 내용을 현재 과정으로 옮겨 편집할 때부터 이 규칙을 적용합니다.
