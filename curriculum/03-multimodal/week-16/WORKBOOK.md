# 16주 실습 워크북 — 한 모델의 재현 범위 확정과 최종 설명

[주차 목표·자료](README.md) → 이 워크북 → [완료 체크](README.md#checklist)

정답 구현 코드는 직접 작성합니다. 먼저 종이에 계산하고 아래 예상 결과와 비교합니다. 수치 예제는 교육용으로 지정한 입력이며, 모델 학습 성공을 보장하는 실측 결과가 아닙니다.

## 1. 완성 수준을 먼저 선언

| 수준 | 의미 |
|---|---|
| 기본 학습 완주 | 내 dense LM과 작은 이미지 경로를 작성하고 학습·검사 |
| 목표 구조 축소 통합 | GDN/QSA/MoE/GR/PLE/vision/merger/위치/cache를 추가 |
| reference 대조 | 동일 작은 가중치로 공식 모듈/층/전체 중 수행한 범위 |
| 원본 성능 재현 | 이번 과정의 목표가 아님 |

기본 단계를 통과했다고 목표 전체를 재현한 것은 아닙니다. 전체 logits 대조가 미완료여도 지금까지 무엇을 이해하고 검증했는지 정확히 보고할 수 있습니다.

## 2. 최종 보고서에 넣을 표

| 구성요소 | 내 파일/노트 | 사용한 source | 고정 입력 | 검사 결과 | 원본과 다른 점 |
|---|---|---|---|---|---|
| text embedding/attention | 작성 | 작성 | 작성 | 통과/실패/미실행 | 작성 |
| GDN/QSA/MoE/GR/PLE | 각각 작성 | 작성 | 작성 | 작성 | 작성 |
| vision/merger/position | 각각 작성 | 작성 | 작성 | 작성 | 작성 |
| cache/학습 | 각각 작성 | 작성 | 작성 | 작성 | 작성 |

가중치 규모·vocab·hash table·image resize·frame sampling·timestamp·MTP·kernel·optimizer·학습 데이터의 차이를 남깁니다. “작게 만들었다”라는 한 문장으로 모든 차이를 합치지 않습니다.

## 3. 20분 설명 순서

1. 텍스트/이미지/영상에서 어떤 tensor가 만들어지는가.
2. Transformer의 attention과 FFN이 목표에서 어떻게 바뀌는가.
3. recurrent state와 KV/indexer/PLE state가 어떻게 다른가.
4. 내 구현에서 선택적으로 줄인 것과 그대로 유지한 것은 무엇인가.
5. 맞다고 판단한 수치 증거와 아직 실패하는 사례는 무엇인가.

같은 설명을 듣는 GPT에게 완성 코드가 아니라 “내 설명의 모순과 누락된 가정”을 찾아 달라고 요청합니다. 지적은 source/fixture로 다시 확인합니다.

## 4. 재실행 점검

새 실행에서 config·사전·weight·환경 버전·seed·fixture를 읽어 결과를 재현합니다. 원본 모델 전체 다운로드가 필요한 절차와 내 작은 실습을 분리합니다. 긴 기록은 [기록 규칙](../../WRITING.md)에 따라 NOTES 파일로 나누고 이 주차 README에 최신 위치를 남깁니다.
